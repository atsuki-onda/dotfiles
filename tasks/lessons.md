# 教訓

このリポジトリで受けた修正と、同じ失敗を繰り返さないためのルール。

## シェル設定は起動経路を両方試してから完了と言う

**2026-09-12 / 指摘: 「他のディレクトリで cc が使えなくなった」**

`~/.local/bin`（`claude` の実体がある場所）を PATH に足す処理を `.zprofile` にだけ書いた。
`.zprofile` はログインシェルしか読まないため、非ログインの対話シェル（別シェルから起動した
`zsh`、エディタの統合ターミナルなど）では `claude` が見つからず、`cc` エイリアスが
`command not found` になった。

検証時に `zsh -lic`（ログイン）だけを試して「クリーンなログインシェルで解決する」と
報告したのが原因。起動経路という別の軸を潰していなかった。

**ルール**

- zsh の設定を変えたら、必ず `zsh -lic` と `zsh -ic` の両方で確認する
- PATH は `zsh/path.zsh` に集約し、`.zprofile` と `.zshrc` の両方から読ませる。
  二重読み込みで重複しないよう冪等に書く
- 「クリーンな環境で動いた」は 1 パターンを潰しただけ。同じ機能に複数の起動経路が
  あるなら、全部の経路を列挙してから検証する
- 検証で潰した穴は `doctor.sh` に検査として残す。次に踏まないようにする

## 変更前の挙動と比べてから原因を断定する

同じ指摘のとき、まず変更前のコミットの設定を一時 HOME に展開して再現を取った。
結果、この穴は変更前から存在していた（親プロセスから PATH を継承していたため
表面化していなかっただけ）と分かり、「自分が壊した」という誤った説明を避けられた。

**ルール**: 「〜できなくなった」と言われたら、直前の変更を疑う前に変更前の状態で
再現するかを確かめる。git があるので数分でできる。
